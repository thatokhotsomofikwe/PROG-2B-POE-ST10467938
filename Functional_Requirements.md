RaceDay Functional Requirements

1. Introduction

This document defines the main functional requirements identified for the RaceDay South African Road Running, Walking and Cycling Event Management System.

Functional requirements describe what the system is expected to do.



2. User Management

FR01 — User Registration

The system shall allow new Participants and Organisers to create user accounts.

FR02 — User Login

The system shall allow registered users to securely log into the system.

FR03 — User Roles

The system shall assign users an appropriate role, such as Participant or Organiser.

FR04 — Profile Management

The system shall allow authenticated users to view and update their profile information.



3. Event Management

FR05 — View Events

The system shall allow users to view available and upcoming sporting events.

FR06 — Create Events

The system shall allow authorised Organisers to create events.

FR07 — Update Events

The system shall allow authorised Organisers to update event information.

FR08 — Delete Events

The system shall allow authorised Organisers to delete events where permitted.

FR09 — Event Details

The system shall provide details about an event, including relevant date, location and event information.



4. Category Management

FR10 — View Categories

The system shall allow users to view categories associated with an event.

FR11 — Create Categories

The system shall allow authorised Organisers to create event categories.

FR12 — Update Categories

The system shall allow authorised Organisers to update event categories.

FR13 — Delete Categories

The system shall allow authorised Organisers to delete categories where permitted.



5. Enrolment Management

FR14 — Enrol in Event

The system shall allow Participants to enrol in available events.

FR15 — Select Category

The system shall allow Participants to select an appropriate event category during enrolment.

FR16 — View Enrolments

The system shall allow Participants to view their own enrolments.

FR17 — Cancel Enrolment

The system shall allow Participants to cancel an enrolment where permitted.

FR18 — Organiser Enrolment Management

The system shall allow authorised Organisers to view enrolments for their events.



6. Results Management

FR19 — Capture Results

The system shall allow authorised Organisers to capture participant results.

FR20 — Update Results

The system shall allow authorised Organisers to update participant results.

FR21 — View Results

The system shall allow Participants to view their own results.

FR22 — Result History

The system shall allow Participants to view their previous performance information.



7. Route and Weather Information

FR23 — View Route Information

The system shall allow users to view route information associated with an event.

FR24 — Manage Routes

The system shall allow authorised Organisers to manage event route information.

FR25 — Weather Information

The system shall provide available weather information for upcoming events.



8. API Security

FR26 — Authentication

The system shall require users to authenticate before accessing protected functionality.

FR27 — Role-Based Authorisation

The system shall restrict functionality according to the user’s assigned role.

FR28 — Participant Data Access

Participants shall only be able to access their own protected enrolment and result information.



9. Part 2

These functional requirements represent the planned functionality identified during Part 1.

The requirements will be implemented and tested progressively during Part 2 of the RaceDay project.
